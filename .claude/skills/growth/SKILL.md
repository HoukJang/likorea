# Growth 작업 오케스트레이터

목표: 커뮤니티 활성화를 통한 likorea.com 트래픽 증가. 성능(품질) 우선, 토큰 효율 준수.

## 절차

1. **상태 로드**: `.claude/growth/STATE.md`만 읽는다. 리포 전체 재분석 금지.
   - 인자로 특정 작업이 지정되면 그것을, 아니면 백로그 최상위 미완료 항목을 선택한다.
2. **범위 확정**: 선택한 항목과 직접 관련된 파일만 확인한다 (STATE.md에 파일 경로 힌트가 있으면 그것부터).
3. **구현 위임**: 
   - 코드 변경이 2개 파일 이하의 소규모면 직접 구현한다 (에이전트 오버헤드 절약).
   - 그 이상이면 `growth-engineer` 에이전트에 위임한다. 프롬프트에는 대상 파일 경로, 요구사항, 프로젝트 컨벤션(2-space, 세미콜론, single quote)을 명시해 에이전트가 탐색으로 토큰을 낭비하지 않게 한다.
4. **검증**: 변경 범위에 해당하는 테스트만 실행한다 (`cd backend && npm test -- tests/api/<관련>.test.js` 또는 frontend 해당 테스트). 전체 테스트 스위트는 커밋 직전에만.
5. **리뷰**: 변경이 인증/보안/DB 스키마를 건드리면 메인 모델이 직접 diff를 리뷰한다. 단순 UI/설정 변경은 생략.
6. **마무리**: 커밋(명확한 메시지) → 푸시 → `.claude/growth/STATE.md` 갱신 (체크 표시, 완료 이력 추가, 새 발견 사항 백로그 반영).

## 토큰 규칙

- STATE.md 외 문서(ACTIVATION_STRATEGY.md 등)는 필요한 섹션만 offset/limit으로 읽는다.
- 측정 작업은 `traffic-analyst`(haiku), SEO 점검은 `seo-auditor`(haiku)에 위임한다.
- 한 세션에 한 항목 완결이 원칙. 항목이 크면 쪼개서 백로그에 나눠 기록하고 첫 조각만 수행한다.

## 금지

- STATE.md 갱신 없이 세션 종료
- main 브랜치 직접 푸시 (지정된 작업 브랜치 사용)
- 콘텐츠 생성을 이 스킬에서 직접 수행 (CLAUDE.md의 콘텐츠 파이프라인 규칙 준수)
